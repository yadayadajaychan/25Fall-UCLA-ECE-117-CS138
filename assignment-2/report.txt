== Question 1

```
Arch:       amd64-64-little
RELRO:      Partial RELRO
Stack:      Canary found
NX:         NX enabled
PIE:        No PIE (0x400000)
SHSTK:      Enabled
IBT:        Enabled
Stripped:   No
Debuginfo:  Yes
```

- RELRO is Relocation Read-Only.
  Full RELRO makes the Global Offset Table (GOT) read-only after startup.
  Partial means the GOT remains writable.
  This means an attacker can overwrite GOT entries once they can write to
  arbitrary memory.
- A stack canary is a random value placed before the return address that
  the function checks before returning. This prevents buffer overflows
  from being able to hijack control flow. Canaries are only useful
  if the attacker does not know its value, so they can be bypassed
  if the attacker can read memory.
- NX is non-executable memory and prevents execution of memory marked as
  non-executable. These are usually memory that are writable such as
  the stack or heap. While this prevents the execution of injected shellcode,
  it doesn't stop attacks that reuse code, such as ROP or ret2libc.
- PIE is Position Independent Executable and means that the executable
  can be loaded anywhere in memory and work fine. This is useful for
  Address Space Layout Randomization (ASLR), which makes it harder for attackers
  to ROP with random addresses. In this case, it is disabled and has a fixed
  base of `0x400000`.
- SHSTK is a hardware-protected shadow stack which mirrors return addresses 
  and detects tampering of the normal stack's return addresses. This defeats
  many return-address overwrites and ROP techniques, but effectiveness depends
  on hardware and OS support.
- IBT is Indirect Branch Tracking and requires indirect calls/jumps to
  start at special `endbranch` targets. This helps detect jumps to unexpected
  addresses. This makes ROP harder but also depends on hardware and OS support.
- The binary's symbol table and names have not been stripped, making it easier
  for an attacker to find functions and understand control flow better.
- Debuginfo greatly eases reverse engineering and exploitation because it contains
  things like source file name, line numbers, variable names, and type info.
- Taking all this into account this binary is still vulnerable to attacks
  even though the security mitigations raise the difficulty level.

== Question 3

One major issue with symbolic execution is path explosion.
The number of possible execution paths grows exponentially with the
number of conditional branches in the program. Concolic execution
(short for concrete + symbolic execution) mitigates path explosion by
combining concrete execution with symbolic tracking. Instead of
exploring all paths simultaneously, concolic execution runs the
program with specific concrete inputs, following one concrete path at
a time while collecting symbolic constraints along that path. It then
systematically modifies one constraint at a time to generate new
inputs that explore different paths in subsequent runs.

== Question 4

If the stack is executable you can perform the attack by using a
NOP-sled (very large region of NOPs) followed by your shellcode,
so instead of needing to jump to a specific address, you only need
to jump to somewhere in the sled. With a bigger buffer overflow
attack, the probability of success becomes higher.
